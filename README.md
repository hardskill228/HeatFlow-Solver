## Огляд

`HeatFlow Solver` — це курсова робота у форматі вебпроєкту, яка поєднує браузерний інтерфейс, FastAPI-бекенд, PostgreSQL і контейнеризовану інфраструктуру для запуску обчислювальних задач, пов’язаних із моделюванням теплопровідності.

Система підтримує:

- реєстрацію та вхід користувачів
- створення задач із параметрами
- відображення прогресу через WebSocket
- збереження історії задач у PostgreSQL
- сторінку профілю та сторінку рейтингу
- багатосервісне розгортання через `NGINX + 2 API-сервери + PostgreSQL`

## Архітектура

Застосунок побудований як невелика розподілена вебсистема:

```text
Браузер
   -> NGINX
      -> api1
      -> api2
          -> PostgreSQL
```

### Основні компоненти

- `frontend` — клієнтський інтерфейс для входу, створення задач, моніторингу, профілю та рейтингу
- `backend` — API-маршрути, автентифікація, керування задачами та інтеграція з базою даних
- `postgres` — постійне збереження користувачів, токенів, активних задач, черги та історії
- `nginx` — reverse proxy і балансувальник навантаження

## Основні можливості

- асинхронне виконання обчислювальних задач
- відображення прогресу виконання в реальному часі
- збереження історії запусків
- керування задачами: пауза, відновлення, скасування
- робота з кількома API-екземплярами через балансувальник
- локальне розгортання через Docker

## Як користуватись застосунком

### 1. Вхід або створення акаунта

Відкрийте:

```text
http://localhost:8080
```

На сторінці автентифікації доступні дві вкладки:

- `Вхід` — для вже створеного користувача
- `Реєстрація` — для створення нового акаунта

Для створення акаунта потрібно вказати:

- ім'я користувача
- пароль
- підтвердження пароля

Додатково можна розгорнути блок `Додати фото та контактні дані` і заповнити:

- ім'я
- електронну пошту
- фото профілю
- адресу
- місто
- телефон

Ці додаткові поля не є обов'язковими, їх можна оновити пізніше на сторінці профілю.

### 2. Запуск розрахунку

Після входу відкривається головна сторінка `/app`. На ній задаються параметри одновимірної задачі теплопровідності:

- `Кількість вузлів сітки` — просторова дискретизація стрижня
- `Кількість часових кроків` — кількість ітерацій явної різницевої схеми
- `Довжина стрижня L, м` — довжина області моделювання
- `Час моделювання, с` — фізичний час, який покриває розрахунок
- `Коефіцієнт температуропровідності α, м²/с` — параметр матеріалу
- `Початкова температура T₀, °C` — температура внутрішніх вузлів на старті
- `Ліва крайова температура T(0,t), °C` — температура на лівому краї
- `Права крайова температура T(L,t), °C` — температура на правому краї

Після заповнення параметрів натисніть `Запустити розрахунок`.

### 3. Моніторинг задачі

Під час виконання на сторінці відображаються:

- ID задачі
- статус
- воркер, який виконує задачу
- поточний етап
- прогрес у відсотках
- стан WebSocket-з'єднання

Задачу можна:

- призупинити
- відновити
- скасувати

Після завершення показуються:

- максимальна температура
- середня температура
- час виконання
- число Фур'є
- графік температурного профілю

### 4. Профіль

Сторінка профілю доступна за адресою:

```text
http://localhost:8080/profile
```

У профілі можна:

- переглянути дані акаунта
- оновити контактні дані
- змінити відображуване ім'я
- змінити ім'я користувача
- переглянути історію запусків
- відкрити деталі виконаних задач

### 5. Рейтинг

Сторінка рейтингу доступна за адресою:

```text
http://localhost:8080/leaderboard
```

Рейтинг показує користувачів і статистику виконаних задач.

### Локальний запуск бекенду

Якщо потрібно запустити бекенд без повного Docker-стеку:

```bash
docker start heatflow_postgres
source venv/bin/activate
uvicorn backend.server:app --host 0.0.0.0 --port 8000 --reload
```

Адреса:

```text
http://localhost:8000
```

Якщо віртуального середовища ще немає:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r backend/requirements.txt
```

Для локального запуску з базою даних через Docker можна підняти тільки PostgreSQL:

```bash
docker-compose up -d postgres
```

Потім запустити FastAPI:

```bash
source venv/bin/activate
uvicorn backend.server:app --host 0.0.0.0 --port 8000 --reload
```

У цьому режимі застосунок буде доступний напряму на `http://localhost:8000`, без NGINX-балансування.

## Тестування

У проєкті є автоматичні тести для API, логіки задач і базових перевірок frontend-сторінок.

Встановлення залежностей для тестування:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements-dev.txt
```

Запуск тестів:

```bash
python -m pytest -q
```

Що перевіряється:

- реєстрація, повторна реєстрація, вхід і доступ до профілю
- авторизація для захищених API
- створення задачі та передача параметрів моделі
- скасування, пауза й відновлення задачі
- нормалізація параметрів розрахунку
- наявність ключових українських елементів у frontend

Тести не потребують запущеного Docker або PostgreSQL: для API використовується тимчасове файлове сховище і тестові підміни.

Перезапустити всі сервіси:

```bash
docker-compose restart
```

Перескласти API-контейнери після змін у коді:

```bash
docker-compose up -d --build
```

Подивитися логи конкретного сервісу:

```bash
docker-compose logs -f api1
```

```bash
docker exec -it heatflow_postgres psql -U heatflow -d heatflow_db
```

```bash
docker-compose down -v
docker-compose up -d --build
```

## Типові проблеми

### Сторінка не оновилась після зміни HTML або CSS

Перескладіть контейнери:

```bash
docker-compose up -d --build
```

Потім зробіть hard refresh у браузері:

```text
Cmd + Shift + R на macOS
Ctrl + Shift + R на Windows/Linux
```

### Порт 8080 зайнятий

Змініть порт у `docker-compose.yml` для сервісу `nginx`:

```yaml
ports:
  - "8081:80"
```

Після цього запустіть:

```bash
docker-compose up -d --build
```

І відкрийте:

```text
http://localhost:8081
```

### База даних не стартує

Перевірте логи:

```bash
docker-compose logs -f postgres
```

Якщо дані не потрібні, можна повністю скинути volume:

```bash
docker-compose down -v
docker-compose up -d --build
```

## Використання бази даних

PostgreSQL зберігає:

- облікові записи користувачів
- токени автентифікації
- активні задачі
- задачі в черзі
- історію завершених задач
- результати обчислень

Приклад запиту:

```bash
docker exec heatflow_postgres psql -U heatflow -d heatflow_db -c "
SELECT id, username, name, email, address, city, phone, created_at
FROM users
ORDER BY created_at DESC;
"
```

## API та робота із задачами

Основна логіка системи побудована навколо обробки обчислювальних задач. Користувач створює задачу через вебінтерфейс, після чого бекенд приймає параметри, реєструє задачу в системі та запускає або ставить її в чергу залежно від поточного навантаження.

Під час виконання відображаються:

- статус задачі
- поточна стадія обчислення
- відсоток прогресу
- воркер, який виконує задачу
- фінальний результат після завершення

Завдяки поєднанню HTTP API та WebSocket-зв’язку система дозволяє не лише запускати задачі, а й відстежувати їх стан у режимі, близькому до реального часу.
